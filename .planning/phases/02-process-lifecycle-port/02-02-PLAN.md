<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Engine → Claude Code CLI subprocess | `supervisor.py` spawns and controls the CLI at 4 sites; `_wd_kill_tree()` is the single shared termination chokepoint for 6+ callers (`warmpool.py`, `halt.py`) |
| Engine → mailhub child subprocess | `mailhub_runtime.py` spawns `python -m mailhub.serve`; `_reclaim_orphan()` signals a pid read from an on-disk pidfile written by a PAST engine run, not a live `Popen` handle |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04 | Denial of Service | `supervisor.py::_wd_kill_tree()` (chokepoint for 4 spawn sites + 6+ callers) | critical | mitigate | Same `start_new_session` + `os.killpg` split as D-06, applied once to the shared `_wd_kill_tree()` so the fix reaches every caller without touching `warmpool.py`/`halt.py` — this is the highest-traffic kill path in the app (every real Claude Code turn), so it gets its own dedicated real-process-tree test |
| T-02-05 | Denial of Service | `mailhub_runtime.py::start()`/`_reclaim_orphan()` | medium | mitigate | `start_new_session` on `start()`'s `Popen` (L366-370) + `os.killpg()` in `_reclaim_orphan()` (L300-324) so a stale mailhub process from a crashed prior engine run is fully reclaimed, not left with orphaned descendants |
| T-02-06 | Tampering | `mailhub_runtime.py::_reclaim_orphan()`'s pidfile-based kill | medium | accept | The pid is read from an on-disk pidfile from a PAST run, not a live handle — if that pid was reused by an unrelated process before reclaim runs, `os.killpg()` signals the wrong process group. This risk pre-exists the phase (the old `os.kill(pid, 15)` had the same reused-pid exposure at single-process scope); moving to a group signal widens blast radius slightly but the exposure window (stale pidfile from a crashed run, reclaimed at next engine start) is unchanged and not introduced by this fix |

</threat_model>
