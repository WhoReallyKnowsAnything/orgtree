<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| App-internal paths -> plist XML | Label/paths originate from app-controlled sources (package.json appId, resolved install directory), never external/user input, but are still interpolated into an XML file |
| launchd/launchctl CLI output -> app | `launchctl print`/`print-disabled` stdout is explicitly disclaimed by Apple as unstable; `sfltool dumpbtm` is undocumented/private |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|--------------|-----------------|
| T-03-01 | Tampering | `buildPlist()` string interpolation | high | mitigate | `xmlEscape()` applied to every interpolated value (label, paths) before insertion; `plutil -lint` is the secondary gate that would catch a malformed result |
| T-03-02 | Elevation of Privilege | `install()`'s `launchctl bootstrap gui/<uid>` | low | accept | Per-user LaunchAgents in `~/Library/LaunchAgents` always run as the logged-in user, never root/SYSTEM — no Windows-style SID/ACL logic ported, none needed |
| T-03-03 | Tampering | Mixed use of deprecated `launchctl load`/`unload` alongside `bootstrap`/`bootout` | medium | mitigate | Only `bootstrap`/`bootout`/`print`/`print-disabled` used anywhere in launchagent-mac.ts and its tests (D-02); `load`/`unload` never appear in this module |
| T-03-04 | Information Disclosure | `StandardOutPath`/`StandardErrorPath` log file locations | low | accept | Log paths are passed in by the caller (Plan 02) using the same user-owned log directory convention as the rest of the app; no new exposure surface introduced by this module |

</threat_model>
