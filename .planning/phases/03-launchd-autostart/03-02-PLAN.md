<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| detectState() classification -> user-facing dialog | The 'disabled' state (from an undocumented `sfltool` signal, in part) drives what the user is told and which System Settings URL is opened |
| `dialog.showMessageBox` response index -> `shell.openExternal` | A hardcoded, literal deep-link URL, not derived from any dynamic input |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|--------------|-----------------|
| T-03-05 | Tampering | `shell.openExternal(LOGIN_ITEMS_SETTINGS_URL)` call site | medium | mitigate | `LOGIN_ITEMS_SETTINGS_URL` is a fixed literal constant exported from launchagent-mac.ts, never interpolated from detectState()'s output or any other dynamic/external value |
| T-03-06 | Denial of Service (self) | Repeated `install()` attempts on every darwin launch if `plutil -lint` keeps failing | low | mitigate | `install()` is attempted at most once per app launch (not retried in a loop within a session); failures are caught and logged via `console.warn`, never retried automatically |
| T-03-07 | Information Disclosure | Remediation dialog content | low | accept | The dialog only names the Login Items & Extensions settings pane, never log file contents or paths, matching `crashReportDialog`'s existing precedent of describing rather than dumping sensitive data |

</threat_model>
