</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| main → renderer broadcast (`open-settings` event) | Main-process-initiated only; the renderer trusts it exactly as it already trusts the existing `open-org` broadcast — no external input crosses this boundary. |
| Native App Menu (OS surface) | Rendered entirely by the OS; no untrusted input reaches it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-04 | Tampering | New `open-settings` DesktopEvent broadcast | low | accept | Broadcast carries `data: null`; the renderer only flips an existing boolean (`showSettings`), no state a compromised main process could not already alter through existing broadcasts. |
| T-04-05 | Elevation of Privilege | `createMainWindow()`/`show()` recreate path | medium | mitigate | The recreate path must call the exact same `configureWindow(...)`/`webPreferences` (contextIsolation, sandbox, nodeIntegration: false) as the startup path via one shared helper — never a second, looser construction path, since a divergent recreate path is exactly how a sandboxing regression would silently ship. |
| T-04-06 | Information Disclosure | `trayIcon()`'s bitmap derivation | low | accept | Operates only on already-bundled, already-trusted icon bytes (the same asset `runtimeIcon()` already loads); no new file path or user-controlled input is introduced. |

</threat_model>
