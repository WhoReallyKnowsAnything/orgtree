Add a new `PosixTree` class directly after `WindowsTree` (before `watch()`), replicating `WindowsTree`'s exact public surface (`__init__(self, engine_pid, parent_pid)`, `.arm()`, `.wait()`, `.terminate(self, code=0, stalled=None)`, `.close()`, `.armed`) per PATTERNS.md's interface contract:
- `__init__` stores `engine_pid`/`parent_pid` and sets `self.armed = False` — no OS handles to open on POSIX; do not duplicate the launch.py self-setpgid fix here, that belongs to Task 2's engine-side change, not the guardian.
- `arm()` is a no-op that sets `self.armed = True` (RESEARCH.md Open Question 2's recommendation: POSIX ownership is by `watch`, not membership, so there is no separate assignment call).
- `wait()` opens one `select.kqueue()`, registers `EVFILT_PROC`/`NOTE_EXIT` kevents (`KQ_EV_ADD | KQ_EV_ONESHOT`) for `engine_pid` and, if set, `parent_pid`, blocks on a single `kq.control(None, 1)` call, and closes the kqueue in a `finally` (Pattern 1, verified live in RESEARCH.md against Darwin arm64 Python 3.10.13).
- `terminate(code=0, stalled=None)` loops with the same 10-second stall deadline and `time.sleep(0.02)` poll cadence as `WindowsTree.terminate()`: each iteration, enumerate live descendants of `engine_pid` by shelling out to `ps -axo pid=,ppid=` and walking the ppid-to-children map (Pattern 2's `live_descendants` logic), union with `engine_pid` itself, resolve each pid to its `os.getpgid()` (skip `ProcessLookupError`), `os.killpg(pgid, signal.SIGKILL)` every distinct pgid found, then individually `os.kill(pid, signal.SIGKILL)` any still-listed pid (skip `ProcessLookupError` on both), re-enumerate, and return once the descendant set is empty — call `stalled(len(remaining))` and re-arm the 10s deadline exactly once per stall window, matching `WindowsTree.terminate()`'s callback cadence.
- `close()` is a no-op (no OS handles held).

Wire the dispatch in `watch()` (currently lines 242-244: `if os.name != "nt": raise RuntimeError(...)` then `tree = WindowsTree(engine, parent)`) into an `if os.name == "nt": tree = WindowsTree(engine, parent) else: tree = PosixTree(engine, parent)` branch — do not touch anything else in `watch()` (PATTERNS.md: the handshake, diagnostic-write callback, and finally-block ordering are shared and platform-agnostic already).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Guardian process <-> engine process tree | Guardian holds SIGKILL authority over `engine_pid` and its enumerated descendants; a scope error extends or restricts that authority unintentionally |
| Guardian process <-> host/desktop-shell process | Before the `launch.py` self-setpgid(0, 0) fix, the engine inherits the Electron desktop shell's process group; a `killpg` on that group crosses into a process the guardian must never touch |
| Guardian subprocess environment <-> parent engine environment | `arm_process_lifetime()`'s env allowlist controls what the desktop/provider environment leaks into the long-lived guardian subprocess |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.1-01 | Denial of Service | `PosixTree.terminate()` / `engine/launch.py::main()` | high | mitigate | self-setpgid(0, 0) in launch.py::main() before arm_process_lifetime()/any provider spawn (Task 2) plus enumerate-then-sweep design (Task 1) so killpg never targets an inherited group containing the desktop shell; verified by test_teardown_spares_unrelated_process_in_inherited_group (Task 2) |
| T-02.1-02 | Denial of Service | `PosixTree.terminate()` | high | mitigate | enumerate-then-sweep by distinct pgid (Task 1, Pattern 2) instead of a single top-level killpg on the engine's own group, so provider CLI processes spawned with start_new_session=True are still reached; verified by test_teardown_sweeps_grandchild_in_escaped_process_group (Task 3) |
| T-02.1-03 | Information Disclosure | `arm_process_lifetime()` env allowlist, process_lifetime.py:41-42 | medium | mitigate | branch the allowlist on os.name so the POSIX guardian subprocess inherits only PATH/HOME/TMPDIR/LANG/LC_ALL, not the Windows-only set nor the full parent environment (Task 1) |
| T-02.1-04 | Tampering | `PosixTree.wait()` kqueue PID registration | low | accept | PID reuse between capture and kqueue registration is a pre-existing, platform-agnostic residual risk (same exposure exists in the Windows OpenProcess path); the synchronous handoff window plus kqueue's report-pending-event-at-registration behavior is the existing mitigation, unchanged by this phase |
</threat_model>
