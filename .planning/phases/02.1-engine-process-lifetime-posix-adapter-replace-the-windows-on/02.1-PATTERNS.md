RESEARCH.md's flow diagram (lines 96-112) specifies the POSIX composition to plug into this SAME shape:
- `__init__`: pin `engine_pid`/`parent_pid` (RESEARCH.md Pitfall 1 requires the guardian's OWN `setpgid` isolation is a `launch.py` concern, not `PosixTree`'s — do not duplicate it here).
- `wait()`: `kqueue.control([kevent(engine_pid, EVFILT_PROC, NOTE_EXIT), kevent(parent_pid, EVFILT_PROC, NOTE_EXIT)], 0, 0)` then a blocking `kqueue.control(None, 1)` — blocks until EITHER exits, mirroring `WindowsTree.wait()`'s `WaitForMultipleObjects(..., False, ...)` (wait-for-ANY, not wait-for-ALL — same semantics, different primitive).
- `terminate(stalled=...)`: loop — enumerate descendants of `engine_pid` via `ps -axo pid=,ppid=`, `killpg()` every DISTINCT pgid found + `kill()` any straggler pid, re-enumerate until empty or the same stall-deadline/`stalled(...)` callback pattern `WindowsTree.terminate()` already uses (10s deadline, `time.sleep(0.02)` poll, re-arm deadline on stall).
- `armed` flag: set exactly like `WindowsTree.armed` — read by `watch()`'s `except` handler (`if tree and tree.armed: tree.terminate(70)`), so it must be set in `arm()`, not `__init__`.

**`watch()` dispatch pattern to extend** (lines 235-267, read verbatim — this function's structure is NOT to be changed beyond the platform branch):
```python
def watch(root: Path, engine: int, parent: int):
    lock = tree = None
    ready = False
    try:
        lock = RootLock(root)
        diagnostic = root / ".desktop-engine-status.json"
        diagnostic.unlink(missing_ok=True)
        if os.name != "nt":
            raise RuntimeError("no native process ownership adapter for this platform")
        tree = WindowsTree(engine, parent)
        print(json.dumps({"prepared": True, "guardian": os.getpid()}), flush=True)
        if sys.stdin.readline(16).strip() != "arm":
            raise RuntimeError("engine did not acknowledge guardian preparation")
        tree.arm()
        print(json.dumps({"ready": True, "guardian": os.getpid()}), flush=True)
        ready = True
        tree.wait()
        tree.terminate(stalled=lambda active: (root / ".desktop-engine-status.json").write_text(
            json.dumps({"state": "termination_pending", "active": active, "guardian": os.getpid(),
                        "message": "Windows has not completed process termination; root lock remains held", "at": time.time()}), encoding="utf-8"))
        diagnostic.unlink(missing_ok=True)
    except Exception as exc:
        if tree and tree.armed:
            tree.terminate(70)
        if not ready:
            print(json.dumps({"error": str(exc)}), flush=True)
        raise
    finally:
        if tree:
            tree.close()
        if lock:
            lock.close()
```
Planner note: replace `if os.name != "nt": raise RuntimeError(...)` / `tree = WindowsTree(engine, parent)` with an `if os.name == "nt": tree = WindowsTree(...) else: tree = PosixTree(...)` dispatch (or equivalent) — everything downstream (`arm()`, `wait()`, `terminate()`, `armed`, `close()`, the diagnostic-file stall callback, the finally-block ordering of `tree.close()` before `lock.close()`) is platform-agnostic already and must NOT be touched.

### `engine/launch.py` — add self-`setpgid(0, 0)` (utility, request-response)

**Why:** RESEARCH.md Pitfall 1 (lines 229-230+) — the engine process currently inherits the Electron desktop shell's process group (`apps/desktop/main/engine.ts:195` spawns without `detached: true`). Any `killpg()` targeting the engine's group before the group is changed would also kill the Electron parent. The fix is the engine calling `os.setpgid(0, 0)` on itself near startup (POSIX only) so it becomes the leader of its own new group before `PosixTree` sweeps by pgid.

**Analog for the POSIX-only branching convention:** `engine/backend/orgtree/gitrunner.py::run()`, lines 51-72 (already read):
```python
def run(cwd: str, args: list[str], *, timeout: float = 12,
        max_bytes: int = 8 * 1024 * 1024, read: bool = True) -> Result:
    env = os.environ.copy()
    ...
    try:
        with tempfile.TemporaryFile() as out, tempfile.TemporaryFile() as err:
            proc = subprocess.Popen(argv, cwd=cwd, env=env, shell=False,
                                    stdin=subprocess.DEVNULL, stdout=out, stderr=err,
                                    creationflags=subprocess.CREATE_NO_WINDOW if os.name == "nt" else 0,
                                    start_new_session=os.name != "nt")
```
This is the existing project convention for `os.name`-gated POSIX process-group behavior: ternary inline on the `os.name` check, no separate helper function, no try/except around the platform branch itself (the `subprocess.Popen` call's own try/except handles failures uniformly). `launch.py`'s self-`setpgid(0, 0)` should follow the same minimal, inline `if os.name != "nt": os.setpgid(0, 0)` shape — a single guarded statement near process entry (in `main()`, lines 352+, before `arm_process_lifetime(...)` is called at line 361, since the guardian's `PosixTree` needs the engine already in its own group when it later enumerates/kills by pgid).

## Shared Patterns

### POSIX platform-gate idiom
**Source:** `engine/backend/orgtree/gitrunner.py:71-72` and `engine/process_lifetime.py:47-48` (`arm_process_lifetime`'s own guardian spawn)
**Apply to:** Both files in scope — the codebase's established idiom is `os.name != "nt"` / `os.name == "nt"` inline ternaries or single-line `if` guards, never a wrapping platform-abstraction module or class hierarchy beyond the `WindowsTree`/`PosixTree` split RESEARCH.md itself specifies. Do not introduce a new platform-detection utility — reuse the bare `os.name` checks exactly as elsewhere in the file.
```python
creationflags=subprocess.CREATE_NO_WINDOW if os.name == "nt" else 0,
start_new_session=os.name != "nt"
```

### Stall-callback / diagnostic-write pattern
**Source:** `engine/process_lifetime.py:252-254` (`watch()`'s call to `tree.terminate(stalled=...)`)
**Apply to:** `PosixTree.terminate()` — must accept the same `stalled` callback signature (`Callable[[int], None]`, called with an "active count" style value) so `watch()` does not need to change its call site at all across platforms.

### Process-group sweep vs. single top-level kill
**Source:** RESEARCH.md lines 109-112 (verified against `gitrunner.py`'s own per-provider `start_new_session=True` groups)
**Apply to:** `PosixTree.terminate()` only — provider processes (`gitrunner.py`, `codexrun.py`, `antigravityrun.py`) each already own a separate process group for independent graceful-stop. `PosixTree.terminate()` must enumerate all distinct pgids under the engine's descendant tree and `killpg()` each one individually — never a single `killpg()` on just the engine's own new group, or orphaned provider groups survive.
