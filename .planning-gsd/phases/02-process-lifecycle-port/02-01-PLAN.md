<objective>
Port the two purpose-built provider-runner files (`codexrun.py`, `antigravityrun.py`) from Windows-only process-tree termination to POSIX, per D-06: add `start_new_session=(os.name != "nt")` to each `Popen(...)` spawn and swap the POSIX branch's bare `proc.kill()` for `os.killpg(pid, signal.SIGKILL)`, matching `gitrunner.py`'s already-correct, already-proven `_stop()` pattern exactly (immediate SIGKILL, no grace period). This is PROC-03's first and second call sites, closing the exact gap ROADMAP Phase 2's success criterion #3 names by name ("codexrun.py's process, once it spawns with start_new_session like gitrunner.py already does").

Purpose: today, `close()`/`kill_tree()` kill only the parent CLI process; any child it forked (a shell, a tool subprocess) survives as an orphan after "stop" — this is the concrete containment leak PROC-03 exists to close for these two providers.
Output: `codexrun.py` and `antigravityrun.py` fixed and covered by new real-process-tree integration tests that fail on the old code and pass on the fixed code.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Engine → provider CLI subprocess | The engine (trusted) spawns and holds a `Popen` handle to a semi-trusted, third-party CLI binary (`codex`, `agy`) and, transitively, whatever OS-level descendant processes that CLI forks |
| Engine → OS process-group table | `os.killpg()` acts on the OS kernel's process-group table, which is shared with any process that happens to occupy a reused pgid |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Denial of Service | `codexrun.py::CodexProcess.close()` | high | mitigate | Add `start_new_session=(os.name != "nt")` to the `Popen()` at L506-511 so `close()`'s `os.killpg(self.proc.pid, signal.SIGKILL)` (replacing bare `self.proc.kill()`) actually reaches descendants instead of leaving them as orphans after "stop" |
| T-02-02 | Denial of Service | `antigravityrun.py::kill_tree()` | high | mitigate | Same fix pattern: `start_new_session` on the `Popen()` at L756-759 + `os.killpg()` scoped to `kill_tree()`'s POSIX branch (L567-584) |
| T-02-03 | Tampering | Both files' `os.killpg(pid, SIGKILL)` call sites | medium | accept | PID/PGID reuse between the `proc.poll()`/liveness check and the kill call is a narrow, pre-existing OS-level race window; the fix copies `gitrunner.py`'s already-proven pattern (which the codebase already trusts for its own process) and adds no new exposure beyond what that reference implementation already accepts |

</threat_model>
